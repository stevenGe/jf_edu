## 一、总体形态

- **形态**：手机浏览器优先的响应式网页应用（可加装到主屏当 PWA 用），不做原生 App
- **角色**：孩子（打卡、看积分、发起兑换）、家长（审核、录入、管理规则、看报表）
- **单家庭部署**：一台机器跑一个进程 + 一个 SQLite 文件，轻量为主

## 二、技术栈（推荐方案）

| 层 | 选型 | 理由 |
|---|---|---|
| Web 框架 | **FastAPI** | 类型安全、自带校验和 API 文档；后续做 PWA 离线/小程序对接都有基础 |
| 模板渲染 | **Jinja2**（服务端渲染） | 纯 Python 技术栈，不引入 Node/前端构建链 |
| 交互增强 | **HTMX + 少量原生 JS** | 打卡、审核等局部刷新，够用且简单 |
| ORM | **SQLModel** | FastAPI 同作者，Pydantic + SQLAlchemy 合体，写起来省事 |
| 数据库 | **SQLite**（WAL 模式） | 单文件、零运维，符合需求 |
| 样式 | Tailwind（CDN）或手写 CSS | 移动优先 |
| 部署 | uvicorn + systemd；`data/jf_edu.db` 定时备份 | 家里电脑/NAS/便宜云主机均可 |

备选：Flask（更传统，同样能胜任）；Django（自带 admin 但对本项目偏重）。默认用推荐方案，除非您有偏好。

## 三、核心业务设计

### 3.1 积分账本（最重要的设计）

所有加减分都进入**不可删除的流水账**：

```
PointTransaction: id, user_id, rule_id, points(±), status, source(孩子打卡/家长录入/周结算/兑换),
                  note, created_by, created_at, confirmed_at, reversal_of(冲正引用)
```

- 孩子勾选的项先生成 `pending` 流水，家长确认后变 `confirmed` 才计入余额
- 家长录错分只能**冲正**（生成一条反向记录），不能静默改历史——对孩子的信任比数据整洁更重要
- 余额 = 所有 `confirmed` 流水之和，不单独存余额字段（避免对不上账）

### 3.2 打卡模式（需 Review 的关键决策）

推荐 **孩子自报 + 家长确认** 的两段式：

```
孩子自己勾"今天独立完成作业" → 状态 pending → 家长晚上花3分钟批量确认 → 入账
```

理由：让孩子自己操作本身就是所有权练习；同时家长确认保证数据真实。家长也可以直接录入（孩子忘了打卡时补录）。

### 3.3 规则体系

```
Rule: id, name, icon, points, period(daily/weekly), category(学习/习惯/诚实/运动),
      auto_confirm(孩子勾了直接入账还是需确认), daily_limit, active, sort_order
```

- 规则分四类：**学习行为 / 专注习惯 / 诚实条款 / 运动投入**（对应 docs/01 的指标）
- 周项规则周日 21:00 提醒结算
- 规则增删改 = 家长端"家庭会议"功能，改规则留痕（规则历史表）

### 3.4 兑换商店

```
Reward: id, name, icon, cost, stock(可选), active
Redemption: id, reward_id, cost, status(申请/已兑现/已取消), created_at, fulfilled_at
```

- 孩子发起兑换申请 → 扣分冻结 → 家长兑现后标记完成
- 奖励上下架、调价由家长操作（和孩子商量后）

### 3.5 老师反馈（每周一次）

```
TeacherFeedback: id, week, classroom_focus(1-5), homework_independence(1-5),
                 practice_quality(1-5), note, created_at
```

- **只做记录和趋势展示，不直接换算成积分**（避免老师反馈变成扣分压力源，违反 docs/01 的"克制扣分"原则）
- 三个维度对应老师反映的三条现状，周报里画趋势线，看长期变化

### 3.6 周报与徽章

- 周报页：本周得分 vs 上周、各项行为完成率、老师反馈趋势、兑换记录
- 连续徽章：如"连续 7 天独立完成作业"，只增不减（中断不清零历史，只是重新累计）

## 四、页面清单

| 端 | 页面 | 内容 |
|---|---|---|
| 通用 | 登录 | 孩子：4 位数字 PIN；家长：密码 |
| 孩子端 | 今日打卡 | 今日可做项卡片、一键勾选、pending 状态提示 |
| 孩子端 | 我的积分 | 余额、今日 +N、连续天数、徽章墙 |
| 孩子端 | 兑换商店 | 商品列表、发起兑换、我的兑换记录 |
| 孩子端 | 流水 | 我赚过的每一分 |
| 家长端 | 今日审核 | pending 流水批量确认/驳回 |
| 家长端 | 手动记账 | 加减分（选规则或自定义，必填备注） |
| 家长端 | 老师反馈录入 | 每周五分钟填三个维度+备注 |
| 家长端 | 规则管理 | 行为规则、兑换商品的增删改 |
| 家长端 | 周报/报表 | 趋势图、完成率、导出 |

## 五、数据模型总览

```
User(id, role, name, pin_hash/password_hash)
Rule / RuleHistory
PointTransaction（流水账，含 status 与冲正）
Reward / Redemption
TeacherFeedback
Badge（连续成就）
```

时区统一 `Asia/Shanghai`；"一天"以自然日 0 点为界，周项周日结算。

## 七、里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M1 最小可用 | 登录、规则种子数据、孩子打卡、家长确认、流水与余额 | 全家能用它真实跑起来第一周 |
| M2 完整闭环 | 兑换商店、周项结算、老师反馈、周报 | 一次完整兑换走通 |
| M3 体验增强 | 趋势图表、徽章、PWA 加主屏、数据备份 | 孩子愿意每天自己打开 |
| M4 可选 | 导出、多孩子支持、通知提醒 | 按需 |

**M1 完成后即停止开发，先用两周**——规则数字大概率要调，真实使用反馈比堆功能重要。

## 九、M1 实施记录

实际交付范围（相对原计划微调）：

- 原计划：登录、打卡、确认、流水余额
- 额外加入：规则管理页（调分值/次数/上下架）、手动记账与冲正、设置页（改密码/PIN/添加家长）——
  因为“先用两周再迭代”的方法论要求能快速调规则数字
- 纯服务端渲染 + 原生表单，未引入 HTMX（降低依赖，M3 体验增强时再评估）
- 时间统一存上海本地墙钟时间（SQLModel 需显式用 NaiveDatetime 类型标注）
- 安全：pbkdf2 密码哈希、签名 Cookie 会话、CSRF 校验、登录限流
